# Arcana Duel システム仕様書

友人同士でインターネット越しに対戦できる、MTG風トレーディングカードゲーム。
カードはオリジナルを外部で作成してインポートする（[カードインポート仕様](カードインポート仕様.md)）。

## 1. システム構成

```
 ┌──────────── プレイヤーAのPC ────────────┐            ┌──────────── プレイヤーBのPC ────────────┐
 │ ブラウザUI ⇄(WS /ui)⇄ ローカルアプリ     │            │ ローカルアプリ ⇄(WS /ui)⇄ ブラウザUI     │
 │  (app/public)       (app/main.js)       │            │ (app/main.js)       (app/public)        │
 │                     ├ ルールエンジン      │            │                                        │
 │                     ├ AI                │            │                                        │
 │                     └ data/(所持・デッキ) │            │                                        │
 └───────────────┬────────────────────────┘            └───────────────┬────────────────────────┘
                 │ WebSocket                                          │ WebSocket
                 └──────────────► 中継サーバー (server/relay.js) ◄───────┘
                                  マッチング・メッセージ中継のみ
```

| コンポーネント | 役割 |
|---|---|
| ローカルアプリ `app/main.js` | 各プレイヤーのPCで起動。`http://localhost:3000` でUIを提供し、所持カード・デッキ・ゴールド・インポート済みセットを `data/` に保存 |
| ブラウザUI `app/public/` | 画面表示と操作。ローカルアプリとだけ通信する（外部には出ない） |
| ルールエンジン `engine/` | ターン進行・優先権・スタック・戦闘・状況起因処理などを実装。UI・通信から独立 |
| 中継サーバー `server/relay.js` | ランダムマッチ・ルーム（6桁コード）によるマッチングと、2者間メッセージの中継。ゲーム内容は解釈しない |

### 中継サーバーの置き方（どれか1つ）
1. **友人の1人がサーバー役**: `start-relay.bat`（または `npm run relay`）を起動し、ルーターでTCP 7700をポート開放。相手は設定画面でサーバーURLに `ws://<グローバルIP>:7700` を入れる
2. **VPS／クラウドに常駐**: `node server/relay.js 7700`。TLS終端（nginx等）を置けば `wss://` で利用可
3. **同一LAN**: サーバー役PCのLAN内IP（例 `ws://192.168.1.10:7700`）を指定

アプリ起動時に `--relay` を付けるとアプリ内で中継サーバーも同時に起動します。

### 対戦の権威モデル
- ルーム作成側（またはランダムマッチで先に待っていた側）が **ホスト** となり、ホストのアプリでルールエンジンを実行する
- ゲストは操作（アクション）をホストに送り、ホストは各プレイヤーに見せてよい情報だけを含む **ビュー**（相手の手札・ライブラリー内容を除外）を送る
- 友人間で遊ぶ前提のため、ホストの改ざん対策（コミットメント方式シャッフル等）は対象外（§7 参照）

## 2. 画面仕様

| 画面 | 内容 |
|---|---|
| トップ | プレイヤー名・ゴールド・戦績表示。①対戦 ②デッキ作成 ③カード入手・売却 ⚙設定・カードインポート を選択 |
| ① 対戦 | 使用デッキ選択。**通信対戦**: ランダムマッチ / ルーム作成（コード表示）/ ルーム参加（コード入力）。**AI対戦**。待機中はキャンセル可 |
| 対戦（盤面） | 相手・自分のライフ/手札/ライブラリー/墓地/追放、戦場（土地と非土地を分けて表示）、ステップ表示、スタック、指示文とボタン、手札、右側にカード拡大プレビューとログ、投了 |
| ② デッキ作成 | 左: 全カード一覧（色・タイプ・テキスト検索・所持のみフィルタ、所持数表示）。クリックで追加／右クリックで削除。右: デッキ一覧（タイプ別）、枚数、マナ・カーブ、検証結果、保存・削除・土地自動調整 |
| ③ カード入手・売却 | ブースターパック購入（開封演出）、シングル購入、売却 |
| ⚙ 設定 | プレイヤー名、中継サーバーURL、全ステップ停止設定、カードセットのインポート／削除、読み込みエラー表示 |

### 盤面の操作
- 緑に光るカード = 今使える（手札: プレイ／唱える、戦場: マナを出す・能力起動）
- 対象が必要な場合は黄色に光る候補（パーマネント・プレイヤー欄・スタック上の呪文・候補ボタン）をクリック
- 攻撃: 攻撃させるクリーチャーをクリックで選択 →「攻撃する」
- ブロック: 自分のクリーチャー → 相手の攻撃クリーチャー の順にクリック →「ブロック決定」
- 優先権の自動パス: 使えるカードがない場合や、自分のスタック上の呪文に対しては自動でパス。既定の停止点は「自分のメイン1/2・自分のブロック後・相手の攻撃後/ブロック後・相手の終了ステップ」。設定で全ステップ停止も可能
- マナの支払いは自動（マナ・プール → 未タップのマナ源の順に最適割当て）。土地をクリックして手動でマナを出すことも可能

## 3. ゲームルール（実装範囲）

MTG総合ルールに準拠し、以下を実装。

- **デッキ**: 60枚以上、同名カード4枚まで（基本土地は無制限）。初期ライフ20、初期手札7枚
- **マリガン**: ロンドン・マリガン（7枚引き直し、キープ時にマリガン回数分をライブラリーの下へ）
- **ターン構造**: アンタップ → アップキープ → ドロー（先攻1ターン目はドローなし）→ 第1メイン → 戦闘（開始／攻撃指定／ブロック指定／先制攻撃ダメージ／戦闘ダメージ／終了）→ 第2メイン → 終了 → クリンナップ（手札7枚超過分を捨てる、ダメージ・ターン終了時効果の解除）
- **優先権とスタック**: 両者連続パスで最上段を解決／ステップ移行。インスタント・瞬速はいつでも、それ以外はソーサリー・タイミング。土地は1ターン1枚
- **マナ**: 5色＋無色、ステップ終了時にマナ・プールは空になる
- **戦闘**: 召喚酔い、警戒、防衛、飛行／到達、威迫、先制攻撃・二段攻撃、トランプル（致死ダメージ割り当て後の超過）、接死（1点で致死扱い）、絆魂、複数ブロック
- **対象**: 呪禁、解決時の対象再チェック（全対象不正で打ち消し）
- **誘発型能力**: APNAP順でスタックへ、対象選択
- **占術**: ライブラリーの上のカードを見て、一番下へ送るか上に残すかを選ぶ
- **条件付き効果（共鳴など）**: 解決時に条件を判定し、満たした効果だけ実行
- **強制ループ**: 同一ターン内で解決が300回を超えたら引き分け
- **状況起因処理**: ライフ0以下・空ライブラリーからのドローで敗北、タフネス0以下、致死ダメージ、接死、破壊不能、不正なオーラ、装備の外れ、レジェンド・ルール（新しい方を残す）、トークンの消滅
- **領域移動**: 移動したカードは新しいオブジェクトになる（対象・効果は引き継がない）
- **勝敗**: 敗北条件、投了、切断（相手切断時は勝利扱い）

簡略化している点: レジェンド・ルールでの選択（新しい方を自動で残す）、ダメージ割り振り順（ブロック順）、捨てる効果の選択は解決後に実施。

## 5. 通信プロトコル

### 5.1 アプリ ⇄ 中継サーバー（WebSocket, JSON）
| 方向 | メッセージ |
|---|---|
| C→S | `{t:"hello", name, protocol:1}` |
| C→S | `{t:"queue"}` / `{t:"createRoom"}` / `{t:"joinRoom", code}` / `{t:"leave"}` |
| C→S | `{t:"relay", data}`（相手にそのまま転送） |
| S→C | `{t:"welcome"}` `{t:"queued"}` `{t:"roomCreated", code}` `{t:"matched", role:"host"|"guest", opponent}` |
| S→C | `{t:"relay", data}` `{t:"opponentLeft"}` `{t:"error", msg}` |

### 5.2 アプリ間（relay の data）
| 方向 | data |
|---|---|
| 双方 | `{k:"deck", format, name, list:[カードID...], cards:[カード定義...], images:{ID: DataURL}}` |
| ホスト→ゲスト | `{k:"view", view}`（状態変化のたび） / `{k:"error", msg}` |
| ゲスト→ホスト | `{k:"action", action}` |

ホストは受信したカード定義を検証し、自分の同IDカードと内容が異なる場合は `opp:<ID>` に改名して衝突を避けます。

### 5.3 アクション（UI/ゲスト → エンジン）
`pass` / `playLand{cardId}` / `cast{cardId,targets}` / `activate{permId,index,targets}` / `tapMana{permId,color}` /
`mulligan{keep}` / `bottom{cardIds}` / `declareAttackers{attackers}` / `declareBlockers{blocks:[{blocker,attacker}]}` /
`discard{cardIds}` / `chooseTargets{targets}` / `setStops{stops}` / `concede`

ビューには `actions`（今実行できる合法手と各対象スロットの候補）が含まれ、UIとAIはこれを元に操作します。

## 6. ディレクトリ構成

```
arcana-duel/
├─ app/main.js            ローカルアプリ（HTTP + WebSocket）
├─ app/lib/               cardstore（セット読込・インポート）/ profile（所持・ショップ）/ session（対戦管理）/ decks
├─ app/public/            ブラウザUI（HTML/CSS/JS, ビルド不要）
├─ engine/                game（ルール）/ cards（カード正規化・検証）/ mana / ai
├─ server/relay.js        中継サーバー
├─ sets/starter/          第1弾「アルカナの夜明け」（49枚・スターター配布）
├─ sets/ruins/            第2弾「遺跡の目覚め」（61枚・パックで入手）
├─ data/                  ユーザーデータ（自動生成: profile.json, インポートしたセット）
├─ docs/                  仕様書
├─ tools/                 セット生成スクリプト（build-starter / build-ruins）と絵柄生成（art.js）
├─ test/                  自動テスト（AI対戦300戦シミュレーション、新ルールの単体テスト、オンライン対戦統合テスト）
└─ start.bat / start.sh / start-relay.bat
```
